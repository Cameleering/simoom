How it was measured

Machines and fairness

  • Server: DigitalOcean c-4 droplets, 4 dedicated vCPUs, Bangalore region, Ubuntu 24.04, a network card with one receive queue.
  • Three lanes: each with its own server droplet and two load droplets. simoom ran in every lane and every round, so every server is compared with simoom on the same droplet, with the same load machines, in the same round.
  • Rotation: the server droplets rotate between rounds, so each lane meets each droplet. The published ratio is the median of the per-round ratios.
  • Open loop: requests are sent at a fixed rate whatever the server does, so a slow server can't slow the load down and hide its own latency.

What is counted

  • Throughput: the highest steady rate at which 99% of answers arrive within 1 ms (5 ms for new connections, downloads and HTTP/2) with no errors. A run that stalls counts as a miss.
  • Rounds: round 1 ran every scenario for every server. Rounds 2 and 3 repeated the status endpoint at 256 clients, the JSON API, new connections, TLS and CPU on the other two droplets. Each chart says how many rounds it holds.
  • Builds: each server in its fastest documented configuration; the programs and their configuration are in bench/competitors.
  • simoom: the benchmark server with all features, commit a81c368. Its smallest build appears only in the footprint charts.

The review that led to this campaign: docs/benchmark-review.md. The analysis, with every anomaly: campaign 4 analysis. Raw records, scripts and programs: bench/results, bench/cloud.

Common questions

What is the fastest Rust HTTP server?

It depends on the use case. In campaign 4, with 10 Rust servers among the 21 on the same droplets, may-minihttp led plain requests per second by 5–16% and simoom was second; simoom led HTTPS throughput, CPU per request and start-up; actix-web kept the most answers within 1 ms during a traffic spike. Numbers from different machines should not be compared: droplets of the same type differed by up to 7x.

Why p99 under 1 ms instead of maximum requests per second?

A server that answers more requests but makes some of them wait seconds is not faster for the people waiting. The headline figure is the highest steady rate at which 99% of answers arrive within 1 ms, with the load sent at a fixed rate so a slow server cannot slow the load down and hide its latency.

Why are only servers on the same droplet compared?

Droplets of the same type differed by up to 7x for every server in earlier campaigns. A comparison across droplets would measure the machines, not the servers. In campaign 4 simoom ran in every lane and every round, so every server has a simoom run on its own droplet to be compared with.

Can I rerun the benchmarks?

Yes. The scripts are in bench/cloud in the repository, the competitor programs in bench/competitors, and the raw records, HDR logs and analyses in bench/results. bench/cloud/c4-report.py turns the records into the tables on this page, and scripts/size.sh reproduces the size table.

Has anyone else measured simoom?

Not yet. Every figure here was measured by the project. If you measure it differently and get a different number, open an issue with your method.
