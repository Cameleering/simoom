simoom documentation

simoom is an HTTP server you build into a Rust program; these guides show how to write services, add TLS, HTTP/2 and HTTP/3, and keep the build small.

simoom serves HTTP/1.1, HTTP/2 and HTTP/3, does its own TLS 1.3, and runs one event loop per CPU core on epoll, io_uring, IOCP or kqueue. It uses nothing outside the Rust standard library and needs no async runtime. If you have used a Rust web framework before, the main difference is this: a service is a plain function that runs on the loop thread, so it answers fast work at once and hands slow work to a pool or to your own threads.

How the pages are organized

Every guide starts with a short answer under its title, then shows code you can copy. Every Rust example was compiled against simoom 0.1.0 with --features full; examples that need another feature say so. Each guide ends with common questions.

Common questions

Which version do these docs describe?

simoom 0.1.0, the first release. The API can still change before 1.0; breaking changes will be listed in the release notes.

Is there a version of these docs for coding assistants?

Yes. The site publishes llms.txt (a summary with links) and llms-full.txt (every page as plain markdown), and every HTML page has its markdown source next to it. The coding agents guide lists the rules an assistant most often gets wrong.

Where do I report a mistake in the docs?

Open an issue or a pull request on GitHub. Security problems go through a private advisory, as described in SECURITY.md.

simoom

A small, fast HTTP/1.1, HTTP/2 and HTTP/3 server engine you build into Rust programs, with its own TLS 1.3 and nothing but the Rust standard library underneath. It is the HTTP engine of Cameleer.

simoom is a Cameleering project: carry more on less, no claim without a number.
